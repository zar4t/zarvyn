# Contributing

Thanks for your interest in Zarvyn. The project is in its security design phase,
so the most useful contributions right now are reviews of the threat model,
architecture and decision records.

## How to contribute

1. Open an issue describing the problem or idea before sending a large change.
2. Keep pull requests small and focused, with a clear description.
3. Follow the [conventions](docs/CONVENTIONS.md) and the
   [documentation rules](docs/ROADMAP-DOCS.md): nothing is documented before it exists.
4. Never include real credentials, secrets or confidential information. Use
   synthetic data only.

## Developer Certificate of Origin (DCO)

Every commit must be signed off, certifying that you wrote the change or have
the right to submit it under the project's license
([developercertificate.org](https://developercertificate.org)):

```sh
git commit -s -m "docs: describe the change"
```

## Security-sensitive contributions

Offensive material must follow the responsible publication rules in
[SECURITY.md](SECURITY.md). Every pull request is reviewed by the maintainer
before merge.
